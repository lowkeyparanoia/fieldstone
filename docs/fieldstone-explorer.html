What it is

One Go binary, the whole backend

PocketBase proved that a single self-hosted binary can replace a stack of services. Fieldstone keeps that ergonomic core — collections, records, auth, realtime, an admin UI — and re-architects it around interfaces so it scales past a single SQLite file: swap in PostgreSQL, add Redis caching, isolate tenants, run background work, and extend the server with sandboxed WASM instead of recompiling.

Collections & records

Define typed schemas, then CRUD records through a consistent REST API — the same model the admin Record Browser drives.

Realtime

A WebSocket hub fans out create/update/delete events to subscribers with goroutine broadcasts — no polling.

Extensible by design

Interface-based backends, a worker-pool job queue, webhooks, gRPC, and a WASM plugin runtime — bolt on capability without forking the core.

Under the hood

Built on Go concurrency primitives

Worker pools, bounded by semaphores

The job queue starts a worker per named queue (default:5, emails:3, webhooks:10). A buffered channel acts as a semaphore so only N jobs run at once; failures back off exponentially and exhausted retries land in a dead-letter queue.

sem := make(chan struct{}, concurrency)
sem <- struct{}{}        // acquire (blocks at capacity)
go func() {
    defer func(){ <-sem }() // release
    executeJob(job)
}()

A hub that fans out to subscribers

The realtime Manager keeps a registry of WebSocket clients and their subscriptions. When the backend emits an Event, the hub matches interested subscriptions and broadcasts concurrently — each delivery on its own goroutine, guarded by sync.RWMutex.

chi middleware chain graceful shutdown (SIGINT/SIGTERM) context cancellation

Each HTTP request already runs in its own goroutine (Go's net/http); Fieldstone layers timeouts, context propagation, and a 30s drain on shutdown on top.
